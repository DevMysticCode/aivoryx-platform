# Team Rules

1. One ticket = one bounded outcome.
2. Do not mix unrelated refactors with feature work.
3. Update diagrams/ADR when architecture changes.
4. Backend and frontend agree through OpenAPI/contracts.
5. Every production-facing failure gets an actionable error code/reference.
6. Never bypass tenant or permission checks for convenience.
7. Never put secrets in source control.
8. Never assume external API behavior; verify docs/sample payloads.
9. Critical user journeys require automated regression tests.
10. If a requirement is ambiguous, raise it before coding rather than inventing a business rule.
